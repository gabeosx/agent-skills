# Evaluation protocol

Freeze the development briefs, their original inputs and executable assertions before implementation. The baseline is the complete released UX Designer 1.0.0 at the worktree starting commit. The separate confirmation author freezes three original briefs and reports a digest before any development outcome is used. Publish those briefs only after freezing the selected skill.

One fresh implementation agent receives up to two tasks, the frozen skill snapshot and the same fixed implementation prompt. Keep task groupings identical across development rounds. Use new output directories and copy only the relevant starter and brief. A run uses the configured Codex model and service settings across all arms. Available model attribution, elapsed time and usage are in the event log. Keep treatment identities out of actor prompts and keep judges in fresh contexts when possible. Model sampling is uncontrolled.

Capture the actual site in a fresh browser context at 1440, 834 and 390 CSS px. Each interaction scenario starts in a fresh context. Check requirements through browser interactions, rather than by reading the harness or accepting a completion claim. Keep network and data synthetic and local. Review automated accessibility findings and judge blockers separately. Preserve the site, exact brief, browser report, snapshots, run artifacts and outcome even when incomplete.

An independent grader grades randomized anonymous screens against the 100-point rubric. Record preference and confidence for aligned task pairs, candidate versus the original baseline and versus the best prior accepted candidate where distinct. Repeat baseline grades are reported within the relevant blind panel only when a new panel actually rescores the baseline. Report the panel's mean, median and per-dimension deltas and the underlying task-level results. Keep missing evidence out of means and show the denominator. Report all started trials in operational counts. Keep each evaluation round's identity map alongside raw grades after grading.

A candidate advances if it gains at least five mean points over the best accepted revision or wins at least 60% of non-tied development pairs, with concrete evidence. A new acceptance blocker, important behavior regression or material loss in any family prevents promotion. Inspect family losses and opposing scores against rendering before deciding. A broad heuristic comparison on six single draws cannot establish statistical significance. Continue toward three cycles when results justify it and up to five when the next hypothesis is supported. Stop after two meaningfully different successive failures or when evidence gives no defensible next change. Save every attempted snapshot before dispatch.

Freeze the winner and run the original baseline and winner once on each reserved family. Compare confirmation separately and keep feedback out of the released snapshot. A new tuned revision would require fresh confirmation. Preserve all runs locally. No external publish or live account mutation is part of this benchmark.
