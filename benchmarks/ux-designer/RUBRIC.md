# Blind interface rubric

Grade the rendered result against the brief. Use the supplied desktop, tablet, mobile and state screenshots, plus neutral browser test results. Consult source only for a specific unanswered implementation or semantic question. Base every judgment on observable evidence. Mark uncertainties. An empty rendering lacks gradeable aesthetic evidence. Use ties when the differences are negligible or evidence is insufficient.

| Key | Points | Evaluate |
|---|---:|---|
| A | 20 | Visual hierarchy, reading order, grouping, deliberate emphasis, scanability and task-appropriate density. |
| B | 15 | Typeface fit, size and weight hierarchy, line height, measure, tracking, optical alignment and dense numeric readability. |
| C | 20 | Palette, intentional use of color, spacing, balance, proportions, alignment, layers, separators, shadows and visual noise. |
| D | 20 | Coherent identity, fit for audience and task, consistency and appropriate distinction. Value restraint on enterprise screens. |
| E | 15 | Action discoverability, responsive usability, information preservation, controls, accessibility and relevant loading, empty, error or disabled states. |
| F | 10 | Reusable styles and components, semantics, system coherence, layout integrity and implementation quality supported by evidence. |

Anchor each dimension to its own maximum. A score around half indicates structural defects, three quarters indicates generally effective work with specific weaknesses, and near the maximum indicates a convincing result with few demonstrated weaknesses. Use whole points. Report unavailable evidence explicitly.

For each output record the numeric score, a short rationale, specific strengths, specific defects and the most valuable improvement for each dimension. Reference rendered locations and viewports. Give the integer sum, three visually important problems, three effective design decisions, and any blockers. A blocker is a key action that fails, missing required information or interaction, a serious accessibility defect, or a viewport that prevents task completion. Record isolated automation limitations separately. Keep blockers visible apart from aesthetic results.

For every specified pair select one anonymous ID or `tie`, record low, medium or high confidence and explain the observable differences. Aesthetic preference and acceptance blockers are separate judgments.
