# Refactoring UI coverage audit

The source scope is the authors' public table of contents, published design examples and articles, and the official spacing excerpt. This audit uses the chapter inventory to locate concepts and the public examples to verify individual techniques. The treatment of unexcerpted chapters is an interpretation from the published titles and examples. [Book and public examples](https://refactoringui.com/), [spacing excerpt](https://refactoring-ui.nyc3.cdn.digitaloceanspaces.com/Refactoring%20UI%20-%20Start%20with%20too%20much%20white%20space.pdf), [seven design techniques](https://medium.com/refactoring-ui/7-practical-tips-for-cheating-at-design-40c736799886), [Laravel.io redesign](https://medium.com/refactoring-ui/redesigning-laravel-io-c47ac495dff0)

| Published topic | Baseline coverage and gap | Treatment to test |
|---|---|---|
| Starting from Scratch | Tactical notes suggest starting with a feature. The entrypoint opens with mandatory decisions and exact scales. Personality, coarse layout and increasing fidelity are absent. Conflicting stop/inference instructions can stall useful work. | Establish the user's next decision and actual content, then sketch the useful region, choose its visual personality and iterate in the build. Resolve consequential ambiguity and make reversible assumptions. |
| Hierarchy is Everything | Primary versus secondary emphasis and action treatments are solid. Blanket label removal and uppercase metadata can obscure meaning. Document structure and visual emphasis need explicit separation. | Rank information by user task, balance size, weight and contrast, keep semantic structure, and retain labels where meaning or accessibility requires them. |
| Layout and Spacing | Strong spacing discipline, four compulsory widths, fixed control heights and blanket wrapping/stacking. These constrain dense workspaces and larger text. | Choose widths by content and measure, separate within-group and between-group rhythm, and compress the structure in priority order. Preserve useful comparison on narrow screens. |
| Designing Text | Scale, line length and contrast appear. Typeface fit, x-height, line-height by role, tracking, mixed-size baselines and numeric alignment receive thin or prescriptive treatment. | Choose faces through actual content, set roles and line heights, align text baselines, tune optical details and use tabular digits with consistent precision. |
| Working with Color | Fixed indigo and cool gray examples are presented as standards. Several text and feedback tokens are too light for normal text. Dark mode is framed as inversion. | Use neutrals, accent and semantic shade families. Define readable foreground/background roles and test composed and interactive pairs. Choose dark mode pairs separately where supported. |
| Creating Depth | Two-part shadows are present, but padding arithmetic and duplicate elevation categories overstate what tokens can guarantee. Subtle light and intentional overlaps are missing. | Define surface order, use tint or edges before shadows, and test overlaps for clipping and focus visibility. |
| Working with Images | Quality and scrims are mentioned. The notes lack subject intent, crop behavior, text contrast across crops, intended scale and user-supplied cases. | Give a useful image a subject and crop. Test focal point, readability, fallback, intended size and content ownership. |
| Finishing Touches | The baseline covers borders and a few alignment moves. Defaults, empty states, restrained ornament and final pixel critique are thin. | Tune one or two task-specific touches. Check real states and finish with a browser-based edit pass. |
| Leveling Up | A verification checklist exists. It emphasizes overflow, fixed scale compliance and matching controls. Deliberate reference study and visual before/after diagnosis are absent. | Name the specific technique worth borrowing, test it in the same composition, and inspect unassisted reading order and screenshots after editing. |

## Implementation audit

- `--color-text-tertiary` formerly used `#9ca3af`, about 2.54:1 against white. The old red, green and amber status colors were unsuitable as normal foregrounds on white. The old default border at `#d1d5db` was about 1.47:1 against white, so it could not identify a control by itself. A subtle separator can keep low contrast when it carries no essential meaning.
- The CSS globally zeroed margin and padding, removed list spacing, styled every heading and paragraph, and set body colors and type. It could disrupt third-party markup and component CSS when imported into existing sites.
- The v3 Tailwind config overrode familiar utility sizes (for example `p-4` became 4px). The v4 framework uses CSS theme variables and does not discover JavaScript configs automatically. Existing consumers who intentionally adopted the v3 aliases need migration guidance. [Tailwind v4 upgrade guide](https://tailwindcss.com/docs/upgrade-guide#using-a-javascript-config-file), [theme variables](https://tailwindcss.com/docs/theme)
- WCAG 2.2 AA requires 4.5:1 for typical text, 3:1 for qualifying large text and applicable non-text boundaries or states, and minimum target sizing or spacing with specified exceptions. Larger targets often improve touch usability. Accessible names, keyboard interaction, visible focus and status cues need direct checks. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
