# Agent Browser Jev

Give the helper a complete, bounded browser goal and exact non-secret values. Jev reads each new page and chooses the next action; agent-browser executes it. Keep planning, authorization, text composition and final acceptance with the caller. Use a direct browser command when the control is already known.

## Setup

Resolve scripts relative to this skill directory. Run `node scripts/setup.mjs` once; it installs dependencies, reuses agent-browser or installs a local copy, and prompts for an OpenRouter API key with input hidden. An existing `OPENROUTER_API_KEY` or saved key skips the prompt. Never request a key in chat. Select an existing agent-browser executable with `--binary /path/to/agent-browser` when needed. See [README](README.md#install).

## Delegate a goal

```sh
node /path/to/skill/scripts/run.mjs --session current-session \
  --intent "Configure the requested report and save it as a draft. Finish on the report list." \
  --value 'name=Weekly operations'
```

Use the existing authenticated session. Optional `--url https://example.com` opens a caller-supplied starting URL in the same invocation. Login, credentials and OTPs remain with agent-browser's authentication provider, outside model input. Resolve the saved binary via `configuredBrowser()` from `scripts/config.mjs` for direct browser operations; never print the raw configuration.

Delegate the coherent goal once instead of splitting it into individual clicks. Supply all known field values up front. The helper is non-interactive: it reads command arguments and returns one JSON result on stdout. Do not create task, policy, result or evidence files. Existing project permissions and privacy rules still apply. For least privilege, repeat `--allow operation` or `--allow 'operation:Exact accessible name'`; when any rule is supplied, other browser gestures are withheld. See [agent invocation contract](references/usage.md).

## Read the result

The command returns `returnReason`, the final `observation`, missing input, a compact action trace, timings, charges and, when needed, an opaque `resumeToken`.

- Evaluate the returned page against the requested outcome. `reported_complete` is the model's assessment, not proof. A fresh, untruncated observation can supply the evidence without another tool call. Re-observe when the page changed after the call, evidence is missing, the result says `fresh:false`, or the task requires a separate authoritative readback. Do not reopen a dialog just to reconfirm a value already established by the returned page.
- Autocomplete text is a search query, not a committed selection. When the caller supplies an exact prefix for a sole empty text field, try it as a query before requesting an unknown full value. For a goal that signals prefix or suggestion matching, the helper takes one bounded settle read after filling so a debounced menu can appear. Click the matching accessible suggestion and check the selected value before continuing. The helper withholds arrow/Enter selection from autocomplete fields because similar options can commit the wrong record. Use direct caller control for keyboard-only dropdowns and verify the committed selection. Tab is not offered.
- When an autocomplete goal is in a form with a visible Submit button, choosing a suggestion alone does not establish that the form was submitted. Complete that form step after selecting the full matching item; do not submit a prefix or a mismatched suggestion.
- If a listbox exposes option references without names, the helper may read those options' text through their observed references before choosing a unique match. It does not inspect unobserved options or infer labels from position.
- For an explicitly named nested menu path, hover intermediate menu items to reveal each submenu before clicking the final leaf. If an exact requested menu label is absent from an open menu, the helper may hover a plausible observed parent to find a submenu; it must not click another item as a substitute. A parent click can select the wrong item on some menus.
- `input_required` identifies a field whose exact value is missing. Supply it from user instructions or authorized caller work, then resume. Do not invent missing user facts.
- When the goal explicitly asks to enter a table row's value, the helper may copy a uniquely labeled value from the current observed table into a text field. It does not infer from ambiguous rows or arbitrary page text.
- When a full accessibility tree exceeds the bounded model context, the browser adapter retries with a compact, interactive, depth-bounded snapshot. If the compact tree loses every actionable reference, or if it is still too large, expose a marked bounded window from the richer observed tree containing only complete entries and matching browser-issued references; never cut a reference or retain metadata for an omitted control.
- For a goal that changes site state, navigation or typed query text is not completion evidence. Do not offer completion until a matching mutating control such as Save, Post, Subscribe, or Upvote has succeeded; the caller must still verify the returned state.
- For a mutation relative to a named forum and ordering, enter that forum and establish the requested sort before offering the mutation. If a goal requires a new Subscribe action from a particular post page but the forum is already subscribed on its listing, clear the existing subscription there, open the required post, and subscribe from that page; only the final Subscribe is completion evidence. On Reddit-style listings, use the first article's exact comments link for its post page because a title can lead directly to linked media, and ignore nested subscriber-count controls that merely mirror the parent button.
- A handoff or limit means completion was not established. Preserve that result. If later caller work completes the task, distinguish it from the helper's result. An absent target remains a handoff even when stopping was correct.
- An uncertain gesture may already have happened. Observe before deciding what to do next; never blindly repeat it. The sole automatic exception is a button pointer click explicitly refused as covered before dispatch: the helper focuses that same observed button and activates it with Enter.

## Continue the same task

```sh
node /path/to/skill/scripts/run.mjs --resume-token "$RESUME_TOKEN" \
  --value 'Report name=Weekly operations'
```

Resume preserves the original session, binary, action allowlist, goal, completed intents and recent actions. It always observes again and chooses new controls. It does not replay stored references. After caller intervention, add `--context "Dismissed the account notice; continue from the current page"`. Do not pass the starting URL again. The token is encrypted, authenticated, expires after 30 minutes and is valid only with the same configured OpenRouter key. Treat it as private task state; do not log or publish it.

Defaults: 30 actions, 60 decisions, 120 seconds per invocation. Override with `--max-actions` and `--timeout` (milliseconds). Clicks, literal fills, native selects, observed native date segments with a supplied ISO date, checkbox check/uncheck, exact-path file uploads, contextual hover, page scrolling, explicitly requested scrolling to the bottom of one uniquely observed long-text textarea, Enter for ordinary text/search submission, Escape, back and brief waits are supported. Upload only when the user requested it and supplied the exact absolute path. Repeated waits on an unchanged page stop being offered after five attempts. Downloads, authentication, keyboard-only pickers, visual-only widgets and tab management remain direct agent-browser work. Keep the session exclusive during each call; the process-local lock cannot exclude people or other processes.

## Validation

`npm test` runs offline regressions. `npm run gym -- --output /absolute/path/to/new-gym.json` runs the fixed local suites, including the 28-case component matrix. `npm run gym:components -- --output /absolute/path/to/new-components.json` isolates that matrix; see its [coverage and source inventories](references/component-gym.md). When improving the helper, run `npm run gym:study -- --baseline-dir /path/to/baseline/skill --output /absolute/path/to/new-study.json` to compare the baseline and current helper on the same disposable cases and UI variants; inspect the independent conditions and traces before promoting a change. For independent benchmark tasks, run the optional Docker-only `npm run gym:browsergym` lane: it supports BrowserGym MiniWoB and the scoped WebArena-Verified browser-control cohort, lets Jev operate the same page through agent-browser, and scores official benchmark reward rather than Jev's completion claim. Add `--headed` to watch a run through a temporary localhost viewer; do not manually interact with a scored trial. Read the [BrowserGym study workflow](references/browsergym-study.md) before using its external benchmark, benchmark sites, or credential-bearing container. Development studies write private evidence files; ordinary task invocations still return one JSON result without evidence files. `npm run gym:generated -- --output /absolute/path/to/new-generated.json --seed 1234 --cases 3` gives an isolated caller seeded multi-page travel goals and independently checks the saved outcome. `npm run benchmark:projects -- --competitor-dir /path/to/forvela/jev-agent-browser --output /absolute/path/to/new-report.json` runs the controlled same-provider, same-browser comparison. `npm run benchmark:codex -- --suite workflow --output /absolute/path/to/new-comparison.json` compares isolated Codex sessions driving agent-browser directly with sessions using the helper. See [benchmarks and limits](references/benchmarks.md).

For longer unattended benchmark work, use the [checkpointed campaign and persistent localhost dashboard](references/browsergym-campaign.md). Bound duration and provider spend, allow no more than three skill-change-gated retries per development task, keep immutable source snapshots and reward reports, and stop on unmetered charges or infrastructure failures. Predeclare holdout cases at initialization; the runner withholds them until development converges and gives each holdout only one attempt. Keep first-attempt, repaired-development, and untouched-holdout scores separate. The campaign runner does not invent skill fixes; an authorized agent reviews failed traces, makes narrow edits, records a change note, and validates on fresh seeds before treating a fix as general. For a named file-tree target, expand only branches whose observed UI state says they are collapsed; if the requested child has no browser ref, an exact text click is permitted only when that text occurs uniquely inside a visible list item. After one successful target click, assess the result or hand off rather than clicking the same tree item again. For an explicit numeric slider goal, use one keyboard step at a time only when a uniquely observed slider handle has an adjacent numeric readout; confirm that the readout moves toward the requested value before continuing. If the goal identifies the nth checkbox and the observed checkboxes have no names, use their current accessibility order to check only that position; an already checked target needs no toggle. For a menu goal naming an icon class, compare only the small icon token extracted from each visible menu-item ref; hover an observed submenu parent to reveal more items before selecting the exact match, then do not reopen the submenu after a successful target click. Never guess a tree path, slider value, or icon-to-label mapping from benchmark data.

For a separate, self-contained BrowserGym-core integration lane, select `--suite integration` in the study or campaign. Its original tasks test multi-page table-to-form copying, saved preferences, and an approval confirmation, with reward checked from the completed browser state. They are not a public benchmark like MiniWoB and must be reported separately. A uniquely matched, explicitly requested table value may be carried to a later page in the same requested step; a new step or conflicting evidence disables that carryover. See the [study workflow](references/browsergym-study.md) for scope and interpretation.

For BrowserGym WebArena-Verified, select `--suite webarena-verified` and read the [study workflow](references/browsergym-study.md) plus [campaign runbook](references/browsergym-campaign.md). Use only the supported Reddit mutate/navigation cohort; retrieval tasks require arbitrary final answers and are outside this browser-control helper's contract. Start the pinned, scoped environment with `npm run gym:webarena:env`, prove both negative and positive evaluator controls before paid trials, and never pass hidden evaluator expectations to Jev. The adapter may supplement BrowserGym's incomplete Playwright trace with request/response data captured from the same page, but the official WebArena-Verified evaluator remains the sole scorer.
