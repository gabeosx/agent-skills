# Helper behavior and interaction details

Read this reference when a particular control or a handoff needs diagnosis. Ordinary delegation and acceptance are covered in [SKILL.md](../SKILL.archived.md); the argument/output contract is in [usage](usage.md).

## Control-specific behavior

- Relative numeric edits use Jev to bind the destination, goal operand and amount/percentage relationship. Code computes exact decimal alternatives and rechecks the observed source before typing. A persistent ledger permits distinct stably identified records or fields while preventing repeated arithmetic on the same field. Unsupported arithmetic and uncertain identity remain value boundaries. See [numeric value limits](usage.md#relative-numeric-values).

- Autocomplete text is a search query, not a committed selection. When the caller supplies an exact prefix for a sole empty text field, try it as a query before requesting an unknown full value. The helper takes one bounded settle read after text entry so a debounced menu or validation can appear, regardless of goal wording. Click the matching accessible suggestion and check the selected value before continuing. The helper withholds arrow/Enter selection from autocomplete fields because similar options can commit the wrong record. Use direct caller control for keyboard-only dropdowns and verify the committed selection. Tab is not offered.
- When an autocomplete goal is in a form with a visible Submit button, choosing a suggestion alone does not establish that the form was submitted. Complete that form step after selecting the full matching item; do not submit a prefix or a mismatched suggestion.
- Selection review distinguishes entering literal text from selecting an existing item, and compares the current input with visible choice text. These exact string comparisons do not prove commitment. Jev may interpret a goal as allowing any matching item; that assessment stays conditional and does not remove alternative actions.
- A custom readonly textbox can display its selected item while exposing no native value. The adapter records bounded exact display text separately from the native field value through the current browser reference. Jev assesses whether that display belongs to the selection widget and establishes its current item; editable query text and truncated displays cannot provide this selection proof.
- For a requested line addition, the helper can preserve a nonempty textbox’s exact observed value and append supplied literal text on a new line. Plain fill remains whole-field replacement. Exact values are bounded and read only through observed plaintext field references; unreadable, readonly, masked and overlong values do not enable append. A changed value at the pre-dispatch check returns `stale_observation` with `not_dispatched`, rather than overwriting the change. This check is not a database transaction; keep the session exclusive and verify the saved result.
- Observed native numeric spinbuttons can be adjusted one ArrowUp/ArrowDown step at a time, with fresh value readback. The helper does not assume a step size or bounds. Readonly/disabled fields and date segments are excluded from numeric stepping.
- Unique exact text in an unreferenced SVG graphic can be clicked through the browser’s exact-text locator, as with supported tree text. This requires a complete observation without duplicate text or a referenced ancestor. It does not establish what clicking will do, and it does not provide coordinates, drag control or image understanding. Jev must justify the target from the caller goal and read back the result.
- Browser-referenced clickable images can expose bounded literal alt/title/ARIA text, CSS classes and a source filename. Jev interprets this metadata; code does not map classes to operations. A focused action check withholds a proposal when the icon’s meaning is unestablished. This check is fallible, and visual-only controls without usable references remain caller-owned.
- An explicit browser clickability marker can also expose a referenced text-role control, such as a clickable section heading. Its name may combine bounded text owned by that control. Ordinary page text containing words such as “clickable” does not create an affordance. These clicks still require current references, caller authorization and the ordinary action-scope review; input and checkbox controls retain their specialized gestures.
- If a listbox exposes option references without names, the helper may read those options' text through their observed references before choosing a unique match. It does not inspect unobserved options or infer labels from position. For an observed native multiple select, selection actions preserve the other currently selected options. Verify the complete selected set; sequential ordinary option clicks can replace earlier selections. Ambiguous labels or incomplete observations do not authorize a guessed combination.
- For an explicitly named nested menu path, hover intermediate menu items to reveal each submenu before clicking the final leaf. If an exact requested menu label is absent from an open menu, the helper may hover a plausible observed parent to find a submenu; it must not click another item as a substitute. A parent click can select the wrong item on some menus.
- Jev can bind an exact caller-goal span or current plaintext source textbox to an observed destination. Code copies existing bytes, with bounded whole-field or contiguous-span choices; it does not compose missing content. For observed empty fields without an offered fill, independent source questions are prepared together before action selection; a single field keeps its focused question. Speculative lookahead considers at most six field/observation pairs per step; an explicitly selected field can still receive one fresh binding attempt within the ordinary decision and time budget. These assessments offer authorized fill candidates and do not execute gestures. Readonly text can be a source. Source bindings expire when the observation changes, and source text is rechecked before copying. If a fresh readable destination differs from the attempted exact value, `input_not_accepted` returns control before a later commit. Inspect the control and representation; do not simply retry the same fill. An unreadable destination cannot support this exact check.
- `input_required` identifies a field whose exact value is missing. Supply it from user instructions or authorized caller work, then resume. Do not invent missing user facts.
- When the goal explicitly asks to enter a table row's value, the helper may copy a uniquely labeled value from the current observed table into a text field. It does not infer from ambiguous rows or arbitrary page text.
- The adapter derives structural objects from one observed accessibility tree: articles, rows, forms, dialogs and supported collection containers. Controls retain their nearest object and parent relationships; direct text excludes child objects. These facts help Jev interpret repeated controls, but do not establish semantic identity or relevance. Same-role sibling order is not a business ranking.
- Large structured observations use bounded windows of complete control entries with their containing objects. Jev can inspect adjacent windows or choose a section from a bounded directory of that same capture without navigating the website or consuming a browser action. Inspection consumes decisions and time. Browser gestures invalidate the capture and reset its window position; subsequent actions use a fresh observation. Omitted text and limited windows remain explicit.
- If the tree has no usable structure, root controls exceed the bound, or a single object cannot fit, the existing compact interactive/depth-bounded and complete-entry edge fallback applies. Limited observations can omit evidence needed to identify a recipient or object. The caller may need richer inspection; a visible control alone does not establish the target.
## Fixed target execution

For coherent repeated effects, Jev can bind a fixed ranked subset or a complete observed member set, then retain those identities while their scores or states change. The optional `executionContract` records each target's pending, dispatched, satisfied or uncertain state. Membership and effect satisfaction are model assessments, not independent verification. Automatic capture-window inspection covers one page capture; it does not prove that every website page was visited. Multi-page member sets use the general controller rather than the specialized fixed-set executor. See the [execution experiments and limits](execution-contract-experiments.md).

## General controller observations and reviews

These details describe the general controller. The fixed-target path above performs its own binding and per-target effect review. Neither path independently verifies its semantic judgments.

In the general controller, large action sets follow the observed page order and are paged without dropping authorized controls. Each page holds at most 200 actions and about 12,000 serialized action characters; an individual action remains indivisible. Control-name previews are bounded as well. Adjacent choice pages include bounded control-name previews so a visible field or sidebar control is not mistaken for an absent target. Jev can inspect another page of choices without a browser gesture; these choices consume decisions, not browser actions. Paging preserves the observation and authorization boundaries. Menu, tree and slider actions describe observed affordances, not a preselected task solution.

For up to 32 links already present in the bounded observation, the adapter reads destinations through browser-issued references. It strips URL credentials, queries and fragments before using the destination as a navigation hint. A title can link to an external resource instead of the item's own detail page; the hint does not authorize opening an invented URL or prove which item meets the goal.

Jev distinguishes explicit qualified-target conditions (such as rank, time range or ownership within a collection) from page requirements. A proposed effect receives a focused assessment of its own containing object; a mixed collection can contain a valid target. Unknown target evidence withholds that effect while navigation remains available. A correctly scoped complete empty set can satisfy an all-members state goal, while an empty keyword search cannot establish it. These are fallible model judgments.

Jev first distinguishes an ordinary task, a qualified-target predicate and an explicit page condition. Only the last enables a separate page-kind and timing classification, keeping an object category from directly imposing a required page. It retains an exact caller-text span and timing: before an effect, at the effect, at completion, or throughout. Ordinary workflows must not acquire invented constraints. A prior visit does not satisfy an at-effect requirement after leaving that page. An executed effect with its before/action/after readback can explain a legitimate confirmation-page transition; a final-screen condition still applies afterward, without blocking necessary work elsewhere first. Multiple, ambiguous or unrepresented conditions stay unknown and the complete caller intent remains available. These interpretations are advisory model assessments, not independent proof of target, ordering or outcome. They do not replace the caller goal. The selector receives up to four executed before/action/after transitions. Each historical readback keeps at most 2,400 characters of complete boundary and executed-control lines; omissions are marked limited. Retained visits and effects do not duplicate whole histories. These are current-invocation evidence, not an expansion of the saved continuation history.

A separate Jev review checks proposed completion when an explicit page requirement applies or when edited fields and a form remain visible. It also checks proposed handoffs, which can reveal an already-reached goal. The review distinguishes an established outcome, a prepared form still needing its commit, and insufficient evidence. It receives the caller goal, current observation and bounded executed readbacks, without earlier model verdicts; it remains a same-model assessment, not independent verification. An uncommitted assessment reopens action selection. When a handoff remains unfinished, a focused continuation check can select a justified observed route in at most four distinct states per step; an unchanged state cannot trigger repeated continuation attempts. Unresolved work still returns control. Explicit preparation without saving remains valid completion. Proposals and reviews consume the existing decision, time and spend budgets; they do not bypass the action allowlist or invoke another model.

Before executing a proposed click, press, fill, selection or upload, Jev separately assesses the immediate action: navigation, preparation, effect, wrong target, missing prerequisite, already-satisfied state, unsupported value or uncertainty. Navigation toward a prerequisite remains available. For a certain explicit before-effect or at-effect condition, an effect needs positively established context; an unknown ranking cannot be erased by a broad “ready” assessment. A separate literal-assignment question compares the caller’s requested use with the observed field and containing object. That answer stays advisory: a supplied prefix can prepare a search without being the final selected value. The immediate-action review determines whether to withhold the proposed fill; broad content-role categories do not impose a code-level veto. These are fallible model checks, not proof. A rejected proposal returns to selection with all authorized alternatives. Rejected completions and repeated unresolved selections can invoke bounded continuation review before returning a handoff with `withheldActions`, clearly labeled as unexecuted model assessments.

When the caller supplies the exact same text under multiple value keys, code exposes those aliases so the assignment check can consider every authorized use. Wrong-target and other action concerns still apply; repeated text does not authorize an unrelated effect.

When a ready-action assessment conflicts with an inferred page or target condition, one additional Jev review can reconsider whether that condition is actually stated, applies to this immediate action, or is already established for its underlying target. This can distinguish a commit button from the previously selected object. Applicable unresolved conditions remain withheld. The review expires with changed observations or permissions, consumes the existing budget, and cannot reopen a primary wrong-target rejection or opaque icon meaning. It remains a fallible same-model assessment.

Action review also receives bounded current input strings, the latest executed input gesture and subsequent gestures. Exact string equality is only observed text; code does not infer that it was saved or that a save is needed. Jev must distinguish prepared text or a selected suggestion from a requested committed outcome, while respecting preparation-only goals and observed autosave. This evidence adds no model calls. Current native-select option names and selected flags are also shared across selection, action and completion reviews, including names recovered through observed browser references. Missing or bounded option sets stay marked limited. Code does not infer the desired selection or commitment from these flags.

The review identifies the object affected by the immediate control. A dialog inside a record editor may change shared option definitions or templates; editing the record alone does not authorize those changes. Conversely, a record field marked global can still belong only to that record. Adding a record or variant requires an observed new-draft or duplication transition before changing an existing record's identity. These are fallible model judgments, with independent scope verification still required.

For an observed searchbox, or a proposed missing-input return from an editable discovery field, Jev may select an exact contiguous span already in the caller goal as a search query. Code validates whole-word offsets, a 160-character bound and the current observed field, then offers that exact text as a separately authorized fill. It cannot generate a query, infer personal facts or compose missing final content. At most two query derivation attempts occur per step. Each first classifies the field and chooses a start word, then selects a complete exact literal beginning there in a separate decision. Proactive derivation applies only to empty searchboxes; a selected missing-input proposal can still request a new query for a nonempty field. The span binding expires with the observation; saved continuation state does not confer authority on a stale field. Unknown or invalid bindings preserve the missing-input boundary. Ordinary supplied values and caller takeover remain available.

Links with an observed `href` are activated by focusing the observed reference and pressing Enter once, avoiding pointer misses on long wrapped link text. Link-role controls without an `href` use a pointer click; focus can otherwise remain on a different control. This remains the selected link activation and does not directly open an inferred destination URL. Browser-tab handling remains caller-owned.

Current observations determine control values. Model history describes executed gestures without stale references or pre-action slider values. Read back each adjustment, preserve values that already satisfy the goal, and distinguish preparing a form from a requested submission. For a uniquely observed long readonly or disabled text area, an element-scoped scroll can reach the end; verify the resulting prerequisite or unlocked control before proceeding.

For numeric, ordinal and quoted item constraints, Jev binds caller-text spans to observed controls and classifies their relationship. Code normalizes supported whole numeric phrases, compares values, combines text constraints and tracks observed positions. Unsupported phrases remain whole and unrepresented rather than becoming misleading partial numbers. Each interpretation offers an unknown choice; changed observations invalidate page-bound semantic answers even when browser references repeat. Computed comparisons are conditional on model bindings and do not remove authorized candidates. The selector retains the complete goal and all authorized alternatives. These calls consume the existing decision, time and spend budgets. Position history remains local to the invocation, and the caller must independently verify the outcome.

Source, proposed-action and completion reviews receive these conditional numeric and accumulated-position comparisons as well. It checks their bindings against the goal and observation without restarting counts on each content page. Expanding an observed tree branch is navigation toward its descendants; the parent need not have the final target's label. These distinctions prevent the review from withholding correct navigation and arithmetic-based choices merely because the final target is not visible on the current page.

For bounded, complete custom-combobox observations, Jev binds the caller requirement to a field and chooses actual noneditable or executed-selection readbacks as evidence. Editable query equality alone does not establish a selection. A field-specific choice can propose an observed option, opening the picker, or an existing authorized query fill. Action review receives that binding and still approves or withholds the gesture. The preparation question omits already-proposed gestures for the same field value and receives execution history; a changed value permits fresh inspection. This route adds model calls, caps distinct observations at eight and proposals at twelve per step, and can hand back unresolved work. These are model assessments, not independent verification or authority to exceed caller permissions. See the [picker study](picker-commit-study.md) for gains, regressions and limits.

A successful fill into an ordinary textbox can also expose detached suggestions. The helper requires the actual fill/readback and a current bounded list, then asks Jev whether that list supplies values for this field. Caller requirement classification excludes the available options; it is bound to the current observation and caller context. The option request includes focused Noul judgments about each item's full identity and consumes only the proposed item's answer at the ordinary `> 0.5` yes/no boundary. This is an experimental semantic assessment, not calibrated action confidence. Search results, unrelated lists and literal-text requirements do not become mandatory selection steps. Additional questions and non-complete returns remain visible in the result.

Defaults: 30 actions, 60 decisions, 120 seconds per invocation. Override with `--max-actions` and `--timeout` (milliseconds). Clicks, literal fills, native selects, observed native numeric stepping, observed native date segments with a supplied ISO date, checkbox check/uncheck, exact-path file uploads, menu and contextual hover, page scrolling, scrolling inside one uniquely observed long-text textarea when the goal requires it, Enter for ordinary text/search submission, Escape, back and brief waits are supported. Upload only when the user requested it and supplied the exact absolute path. Repeated waits on an unchanged page stop being offered after five attempts. Downloads, authentication, keyboard-only pickers, visual-only widgets and tab management remain direct agent-browser work. Keep the session exclusive during each call; the process-local lock cannot exclude people or other processes.
