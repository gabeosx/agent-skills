# Development and validation

Use this reference when changing the helper or evaluating it. Normal browser delegation does not require running these suites. Resolve commands relative to the skill directory.

For a new adapter or benchmark campaign, also follow the repository's [Benchmark Improvement Loop](../../benchmark-improvement-loop/SKILL.md). Paid or unattended campaigns require authorization covering that work; use the authorization already given, including explicit uncapped work. Passing tests or possessing an API key does not provide it. Older runners may require finite `--deadline` and `--max-usd` values: under uncapped authorization choose documented operational batch limits and continue justified batches without treating those flags as a new user approval gate. Preserve cumulative spending and attempt history across batches. Keep original failures, official reward, independent goal/scope checks, completion reporting and caller assistance distinct.

## Available checks

`node tests/field-binding-live.mjs --qualify --output /absolute/path/to/new-controls.json` qualifies rendered fills, selection, saved outcomes and restoration without a model. Add `--reserved` for the reserved authored variants. Paid comparisons require frozen `--baseline-dir`, `--candidate-dir`, an explicit `--deadline`, `--max-usd` and a new output. `--cases` selects named definitions; `--arms baseline|candidate` produces an explicitly unpaired report; `--prefix-key` changes the supplied key while preserving its exact value and original goal. Qualify the same selected definitions and input profile before paid dispatch, track attempts across all reports, and stop on unknown charges. The server independently audits transient edits, record preservation, query preparation and completion; negatives remain separate. See the [field-binding study](field-binding-study.md) for the rejected classifier and independent caller recovery. Its private caller bridge is an experimental wrapper around the maintained caller machinery, not a new public CLI.

`npm run gym:caller-workflow -- --run-dir /absolute/path/to/study --helper-dir /absolute/path/to/frozen-skill --deadline ISO-UTC-DEADLINE --max-usd APPROVED-LIMIT` compares an independent metered caller alone, Jev alone, and the caller delegating with actual takeover/resume. The run directory must contain a frozen `source-manifest.json`; run the same command with `--preflight` first to qualify browser controls and fresh-state isolation without model calls. The helper directory supplies the frozen scripts, dependencies, skill and references. Each caller gets only the goal, permitted guidance and UI tool results. Persist initial helper returns, caller tools and separate charges; judge composed text separately from necessary string checks. These are authored workflow scenarios, not public benchmark scores. See the [caller workflow study](caller-workflow-study.md) for the frozen design and results.

`npm test` runs offline regressions. `npm run gym -- --output /absolute/path/to/new-gym.json` runs the fixed local suites, including the 28-case component matrix. `npm run gym:components -- --output /absolute/path/to/new-components.json` isolates that matrix; see its [coverage and source inventories](component-gym.md). For a paired local workflow comparison, run `npm run gym:study -- --baseline-dir /path/to/baseline/skill --output /absolute/path/to/new-study.json` to compare the baseline and current helper on the same disposable cases and UI variants; inspect the independent conditions and traces before promoting a change. For independent benchmark tasks, run the optional Docker-only `npm run gym:browsergym` lane: it supports BrowserGym MiniWoB and the scoped WebArena-Verified browser-control cohort, lets Jev operate the same page through agent-browser, and scores official benchmark reward rather than Jev's completion claim. Add `--headed` to watch a run through a temporary localhost viewer; do not manually interact with a scored trial. Read the [BrowserGym study workflow](browsergym-study.md) before using its external benchmark, benchmark sites, or credential-bearing container. Development studies write private evidence files; ordinary task invocations still return one JSON result without evidence files. `npm run gym:generated -- --output /absolute/path/to/new-generated.json --seed 1234 --cases 3` gives an isolated caller seeded multi-page travel goals and independently checks the saved outcome. `npm run benchmark:projects -- --competitor-dir /path/to/forvela/jev-agent-browser --output /absolute/path/to/new-report.json` runs the controlled same-provider, same-browser comparison. `npm run benchmark:codex -- --suite workflow --output /absolute/path/to/new-comparison.json` compares isolated Codex sessions driving agent-browser directly with sessions using the helper. See [benchmarks and limits](benchmarks.md).

`npm run gym:execution -- --output /absolute/path/to/new-execution.json --deadline ISO-UTC-DEADLINE --max-usd APPROVED-LIMIT` checks fixed ranked targets, a large captured member set and two separate negative cases against server-side state. Use an existing explicit paid allowance. Optional `--baseline-dir` adds a paired comparator. These are authored fixtures, not a public benchmark or actual site-pagination claim; see [experiment scope](execution-contract-experiments.md).

For longer benchmark work, use the [checkpointed campaign and persistent localhost dashboard](browsergym-campaign.md). Apply any authorized duration and spend limits, preserve failures and source snapshots, and keep frozen development first attempts, accumulated development results, current-candidate coverage and untouched holdouts separate. A terminal campaign or a collection of repaired tasks does not establish that its final implementation passes the whole set. Read the [change acceptance rules](study-gym.md#accept-a-general-improvement) before changing the helper from benchmark feedback.

For a separate, self-contained BrowserGym-core integration lane, select `--suite integration` in the study or campaign. Its original tasks test multi-page table-to-form copying, saved preferences, and an approval confirmation, with reward checked from the completed browser state. They are not a public benchmark like MiniWoB and must be reported separately. A uniquely matched, explicitly requested table value may be carried to a later page in the same requested step; a new step or conflicting evidence disables that carryover. See the [study workflow](browsergym-study.md) for scope and interpretation.

For BrowserGym WebArena-Verified, select `--suite webarena-verified` and read the [study workflow](browsergym-study.md) plus [campaign runbook](browsergym-campaign.md). The maintained CLI supports the Reddit mutate/navigation cohort; the separately qualified private Shopping Admin prototype is described below. Do not assume site support transfers between those runners; retrieval tasks require arbitrary final answers and are outside this browser-control helper's contract. Start the pinned, scoped environment with `npm run gym:webarena:env`, run `gym:webarena:env -- qualify` and prove both negative and positive evaluator controls before paid trials, and never pass hidden evaluator expectations to Jev. The runner replaces and verifies the persisted backend before each arm; `/init` alone is not a reset. Missing, dirty or stale qualification blocks scoring. Record supplemental scope review independently of official reward and completion reporting. The adapter may supplement BrowserGym's incomplete Playwright trace with request/response data captured from the same page, but the official WebArena-Verified evaluator remains the sole scorer.

For the current readonly/custom-picker regression and its preserved misses, see [control affordance evidence](control-affordance-study.md). The [architecture review](architecture-review.md) maps external feedback to already tested ablations and remaining hypotheses.

For the field-specific picker controller, use the [picker commitment study](picker-commit-study.md). `node tests/picker-commit-live.mjs --qualify --cohort workflow --output /absolute/path/to/new-report.json` exercises rendered controls without a model. Paid comparisons require frozen `--baseline-dir`, `--candidate-dir`, `--deadline` and `--max-usd`; `--cohort transfer` selects the separate authored transfer fixtures; `--cohort detached` tests ordinary textboxes with suggested values, and `--cohort discovery` tests discovery versus constrained effects. Each supports `--qualify` without a model. These inspected fixtures are now development material. `--candidate-only` records a retry rather than inventing a new pair. The component runner also accepts `--deadline` and `--max-usd` and stops on unknown charges.

BrowserGym supports `--arm baseline|candidate` for a named single-arm diagnostic in MiniWoB, integration and WebArena studies. These reports remain unpaired. Smoke controls cannot select a scored arm. Changed harness fingerprints require renewed WebArena reset and evaluator qualification before scored dispatch.

The [Shopping Admin transfer study](public-transfer-study.md) and [RC improvement study](rc-improvement-study.md) document a private qualified prototype, separate from the maintained Reddit adapter. It checks full source-table digests and fresh backend replacement, exposes unrequested product-save changes and a notification server error, and preserves rejected waiting/navigation candidates. Do not assume the maintained CLI supports this additional site or pool its cases with older samples.

For the relative numeric path, `node --test tests/numeric-value.test.mjs tests/numeric-ledger.test.mjs tests/numeric-ledger-review.test.mjs` covers exact arithmetic, semantic-binding provenance, stable record identity, duplicate edits, source/type changes, uncertain dispatch and resume protection after truncated history. `tests/relative-numeric-live.mjs` requires frozen baseline/candidate directories, a new output, explicit deadline and spend cap; run `--qualify` first to prove rendered reachability/restoration without model calls, then score separately. `--holdout` selects the reserved authored definitions; once inspected, they are regression cases. The [numeric study](public-transfer-study.md#relative-numeric-binding) records the first cohort's late qualification, the valid reserved authored comparison and unfinished public pairs.

The adopted target-conditioned numeric binding and bounded advisory resolution also have focused tests in `tests/target-conditioned-numeric.test.mjs`, `tests/target-field-review.test.mjs`, `tests/numeric-resolution.test.mjs` and `tests/numeric-resolution-review.test.mjs`. They cover record-specific field choices, speculative-probe limits, stale proofs and duplicate protection. The [broader RC study](broad-rc-study.md) separates the fresh browser results, exposed retries and forced-resume outcomes; passing these mechanisms does not establish complete target discovery or reliable completion reporting.

Completion review now receives observed field metadata and the original-value numeric ledger, with explicit limits for omitted text, historical readbacks and unsaved values. The condition-review guard withholds a contradictory same-observation override of a target mismatch while retaining navigation and preparation classifications. These changes do not turn model judgments into independent proof or fix every initial target classification. The experimental query fallback, report-qualification prompt and multiselect factorization remain excluded.

## Proportionate validation

For explicitly clickable text-role controls, `node --test tests/explicit-clickable.test.mjs tests/icon-evidence.test.mjs tests/command.test.mjs` covers structural metadata, owned labels, stale references, native-input preservation and transport authorization. The [broader RC study](broad-rc-study.md) keeps scripted transport qualification separate from actual Jev browser results and WebArena transfer.

Choose checks for the changed mechanism and the acceptance claim. Reuse passing results for unchanged source/harness fingerprints; rerun affected checks after changes or failures, and run the required integrated suite before freezing a release candidate. Do not run every paid study or caller-comparison lane for each edit. Use the current frozen Jev RC as the comparison baseline when improving that RC; an external paid caller is a separate experiment requiring authorization and cannot establish standalone Jev improvement.

Astra guidance about lean prompts and fewer approval pauses applies to the engineering workflow. Changes to Jev prompt content, review calls or deterministic controls require evidence on Jev itself; retain authorization and effect-scope invariants rather than assuming another model's judgment transfers.
