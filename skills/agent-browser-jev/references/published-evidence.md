# Other Jev browser projects

Reviewed September 25, 2026 from the projects' public repositories. Their demos and benchmarks use different websites, browser engines, models, clocks and success checks. One compatible project has now been run on our controlled matrix; the rest remain a feature comparison, not a ranking.

| Project | What it offers | How it differs from this skill |
| --- | --- | --- |
| [Browser Use's jev-ultrafast](https://github.com/browser-use/jev-ultrafast) | A compact indexed action space, one Jev request for operation and compatible targets, a headed inspector, and independent checks for its flight demo. Its six alternating flight runs report a 7.1-second median for the newer version. | It uses Browser Harness and its own browser loop. Its flight timing cannot be compared with our report-workflow timing. Its observation and wait optimizations are worth testing in our gym. |
| [Ying-Kai-Liao/jev-browser](https://github.com/Ying-Kai-Liao/jev-browser) | npm package, MCP server and CLI; page diffing, explicit browser checks and a local benchmark with ground-truth tasks. The repository reports 40/42 on its latest set. | It uses Playwright and exposes a broader browser toolkit. Its benchmark is a useful example of publishing misses, but the 40/42 result is not our pass rate or a head-to-head result. |
| [jkudish/jev-browser](https://github.com/jkudish/jev-browser) | npm CLI, MCP server and library; several Jev providers, optional typing model, screenshots, console errors, and credential-aware starts. | Broader distribution and observation features. It launches a Playwright browser rather than operating an existing agent-browser session. |
| [jal-co/jev-agent-browser](https://github.com/jal-co/jev-agent-browser) | A Python adapter that uses Agent Browser, pauses for missing text and resumes through a persistent JSON-lines process. | Closest to our architecture. Our skill uses a one-shot bundled helper with a direct JSON result and an encrypted continuation token; this project keeps a persistent process. Neither published repo establishes a controlled speed or reliability win over the other. |
| [forvela/jev-agent-browser](https://github.com/forvela/jev-agent-browser) | npm package for bounded Jev tasks on agent-browser, with a library adapter and typed handoffs. | The closest same-provider comparison target. A pinned 0.1.7 checkout now has controlled component results below. |
| [tontoko/jev-browser](https://github.com/tontoko/jev-browser) | Playwright SDK, persistent CLI and MCP interface, native commands and deterministic assertions. | Wider developer API and verification surface, with a different browser runtime. It serves a different integration preference. |

## What we can claim

This skill is a convenient way to let Jev operate an **existing agent-browser session** from an installed agent skill. It has bounded actions, exact supplied values, direct results, encrypted short-lived continuation tokens and independent local suites, including a [26-case common-component matrix](component-gym.md). In one measured multi-screen task it reduced complete Codex task time and an API-equivalent cost estimate. In shorter tasks the gain was much smaller and strict checks failed twice. Keyboard-only autocomplete remains outside the helper's completion boundary: it returns control rather than risking a similar wrong record. [The benchmark notes](benchmarks.md) show the successes, failures and current safety behavior.

Against pinned `forvela/jev-agent-browser` 0.1.7 on the same 26 local pages, same natural-language goals, same OpenRouter Decisions endpoint, `typesafe/jev-1.13` model and agent-browser 0.33.2 runtime, this skill passed **26/26** independently verified outcomes and the comparison arm passed **11/26**. The 15 differential cases ran twice more and passed **30/30** versus **0/30**. [Full method, failures and reports](benchmarks.md#controlled-same-stack-project-comparison) are retained.

We can claim a functional coverage advantage over that pinned version on this synthetic matrix. We cannot claim it is universally faster, cheaper or more reliable than every project above. The direct-TypeSafe projects could not be run with the available OpenRouter credential without changing their provider contract, and several use different browser runtimes. Some already offer features this skill does not: provider choice, screenshots, a persistent MCP server, richer extraction, or more complete browser verification.

## What a fair comparison would take

Run each implementation on the same disposable sites and hidden outcome checks, with equivalent goals, values, action budgets and starting state. Record the full task clock, model time, browser time, provider charges, caller-model usage when present, failed attempts and cleanup. Keep native engine advantages visible rather than forcing every project through agent-browser. Repeat several task types, including absent targets, similar autocomplete options, delayed content and longer multi-screen work. The current runner establishes one controlled same-stack comparison. Broader claims require native adapters, credentials and repeated longer tasks for the other projects.

## Using Jev's decision primitives

Reviewed again September 29, 2026 against the [official TypeSafe skill](https://github.com/typesafe-ai/skills/blob/main/skills/typesafe-ai/SKILL.md), [question guide](https://docs.typesafe.ai/primitives), [model limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13), and pinned [Browser Use controller](https://github.com/browser-use/jev-ultrafast/tree/1231850a0bf1a0c0341fe408ef1668dbbfdfac46). A bounded next-action Choice is a supported use. Correct typed requests do not establish that a whole browser workflow is reliable.

| Pattern | Appropriate browser use | What to preserve or test here |
| --- | --- | --- |
| Choice | Select an observed action, source span or compatible target. | Include unknown/no-match when needed; keep target, value and containing object together. Splitting operation and target can lose that relationship. |
| Noul | Judge a specific condition against stated evidence. | Its value is a yes probability, not a separate confidence score. Evaluate thresholds against false actions and caller returns; do not replace every Choice with a threshold. |
| Score | Rank the relevance of independently described objects or regions. | Use explicit levels and retain low-relevance/no-evidence outcomes. A high relevance score is neither authorization nor proof of completion. |
| Speculative fan-out | Ask independent field, option or evidence questions over the same observation in one request. | Consume only the selected branch. A real dependency that constructs new evidence or options still needs a later request. |
| Select then copy | Bind a source span or observed field to its destination. | Code copies exact bytes and checks freshness. Never chain choices to invent arbitrary prose. |
| Retrieve then judge | Rank region summaries, then inspect the selected region with richer context. | Keep omissions visible. Do not silently classify an unseen target as absent. |
| Verify and escalate | Check an evidence-backed claim, or return missing facts and unfinished work to a stronger caller. | Keep the Jev assessment distinct from independent verification and count all caller assistance. |

The [fan-out guidance](https://docs.typesafe.ai/patterns/fan-out) is about independent questions, not assuming that more questions improve quality. Question IDs are not model instructions. Name the actual judgment and its state fields explicitly. Large instructions and unrelated state can degrade Jev; its [jaggedness notes](https://docs.typesafe.ai/model-jaggedness/jev-1.13) also distinguish semantic binding from arithmetic, which remains in code. [Probability distributions and confidence](https://docs.typesafe.ai/confidence) should be retained for evaluation; concentration among options is not overall task correctness.

The operation/target comparison retained the same executor and review stages. On ten self-authored value fixtures, the flat selector reached **6/7 positive goals**, with one unrepresentable exact-copy boundary and **3/3 negative checks**. A short operation/target variant reached **4/7** and falsely completed three unfinished positives. Restoring the full action descriptions and instructions reached **6/7**, with no false completion on this sample, but used **82 calls and $0.012842** versus the paired flat arm's **80 calls and $0.007771**. Total helper time was about 33 seconds in each arm. The later isolated Reddit comparison reached **1/7 full rewards versus 2/7** for flat selection, including an additional handoff on an editing task. The flat selector remains the default. This rejects the tested composition, not all parallel questions.

A narrower retained change prepares exact input bindings before the action selector requests missing input. Independent empty fields share one request; a single field retains focused state, with dependent excerpt selection deferred until needed. An initial shared-state variant lost one local goal and was rejected. The revised version preserved **6/7 positive goals and 3/3 negatives**, with **64 versus 78 calls** and **$0.006061 versus $0.007669** (about 21% less measured cost). On a frozen 39-family MiniWoB comparison at fresh seed 5093 it reached **29/39 versus 28/39** official goals, **28 versus 27** also reported complete, with no completion reports on zero-reward tasks. This broader run used **314 versus 313 calls** and **$0.039046 versus $0.037833**: local savings do not establish general cost reduction. Both arms had zero caller intervention. All 39 families were practiced; scope is independently audited for only four of them, including a premature flight-search failure in both arms.

The result supports preserving relationships and changing when useful evidence becomes available. It does not support splitting every decision, adding arbitrary confidence gates, or claiming unfamiliar-task reliability. Raw failures, frozen controllers and audits remain in `.runs/value-binding-20260929/`; the [capability scorecard](capability-status.md) separates current and historical evidence.

Browser Use's controller also offers a separate generative text helper. Its source keeps that model's role explicit; adopting it here would create an assisted arm with separate caller/model usage. The public flight demonstration does not establish the capability of Jev alone on arbitrary text composition or unfamiliar websites.

The subsequent [goal-discovery experiments](goal-discovery-experiments.md) tested reduced context, Jev stage/target memory, shared reviews and an independent planner from unchanged natural-language goals. Shared task state tied the current controller on external development and unopened instances; narrower target-review state performed worse on counterexamples. Independent planning recovered one verified author-based goal in three cases but caused a wrong ranked-target effect elsewhere. It remains an explicitly assisted experiment, with separate measured usage, rather than a new default capability.
