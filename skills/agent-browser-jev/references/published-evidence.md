# Other Jev browser projects

Reviewed September 25, 2026 from the projects' public repositories. Their demos and benchmarks use different websites, browser engines, models, clocks and success checks. One compatible project has now been run on our controlled matrix; the rest remain a feature comparison, not a ranking.

| Project | What it offers | How it differs from this skill |
| --- | --- | --- |
| [Browser Use's jev-ultrafast](https://github.com/browser-use/jev-ultrafast) | A compact indexed action space, one Jev request for operation and compatible targets, a headed inspector, and independent checks for its flight demo. Its six alternating flight runs report a 7.1-second median for the newer version. | It uses Browser Harness and its own browser loop. Its flight timing cannot be compared with our report-workflow timing. Its observation and wait optimizations are worth testing in our gym. |
| [Ying-Kai-Liao/jev-browser](https://github.com/Ying-Kai-Liao/jev-browser) | npm package, MCP server and CLI; page diffing, explicit browser checks and a local benchmark with ground-truth tasks. The repository reports 40/42 on its latest set. | It uses Playwright and exposes a broader browser toolkit. Its benchmark is a useful example of publishing misses, but the 40/42 result is not our pass rate or a head-to-head result. |
| [jkudish/jev-browser](https://github.com/jkudish/jev-browser) | npm CLI, MCP server and library; several Jev providers, optional typing model, screenshots, console errors, and credential-aware starts. | Broader distribution and observation features. It launches a Playwright browser rather than operating an existing agent-browser session. |
| [jal-co/jev-agent-browser](https://github.com/jal-co/jev-agent-browser) | A Python adapter that uses Agent Browser, pauses for missing text and resumes through a persistent JSON-lines process. | Closest to our architecture. Our skill uses a one-shot bundled helper with a direct JSON result and an encrypted continuation token; this project keeps a persistent process. Neither published repo establishes a controlled speed or reliability win over the other. |
| [forvela/jev-agent-browser](https://github.com/forvela/jev-agent-browser) | npm package for bounded Jev tasks on agent-browser, with a library adapter and typed handoffs. | The closest same-provider comparison target. A pinned 0.1.7 checkout now has controlled component results below. |
| [tontoko/jev-browser](https://github.com/tontoko/jev-browser) | Playwright SDK, persistent CLI and MCP interface, native commands and deterministic assertions. | Wider developer API and verification surface, with a different browser runtime. It serves a different integration preference. |

## What we can claim

This skill is a convenient way to let Jev operate an **existing agent-browser session** from an installed agent skill. It has bounded actions, exact supplied values, direct results, encrypted short-lived continuation tokens and independent local suites, including a [26-case common-component matrix](component-gym.md). In one measured multi-screen task it reduced complete Codex task time and an API-equivalent cost estimate. In shorter tasks the gain was much smaller and strict checks failed twice. Keyboard-only autocomplete remains outside the helper's completion boundary: it returns control rather than risking a similar wrong record. [The benchmark notes](benchmarks.md) show the successes, failures and current safety behavior.

Against pinned `forvela/jev-agent-browser` 0.1.7 on the same 26 local pages, same natural-language goals, same OpenRouter Decisions endpoint, `typesafe/jev-1.13` model and agent-browser 0.33.2 runtime, this skill passed **26/26** independently verified outcomes and the comparison arm passed **11/26**. The 15 differential cases ran twice more and passed **30/30** versus **0/30**. [Full method, failures and reports](benchmarks.md#controlled-same-stack-project-comparison) are retained.

We can claim a functional coverage advantage over that pinned version on this synthetic matrix. We cannot claim it is universally faster, cheaper or more reliable than every project above. The direct-TypeSafe projects could not be run with the available OpenRouter credential without changing their provider contract, and several use different browser runtimes. Some already offer features this skill does not: provider choice, screenshots, a persistent MCP server, richer extraction, or more complete browser verification.

## What a fair comparison would take

Run each implementation on the same disposable sites and hidden outcome checks, with equivalent goals, values, action budgets and starting state. Record the full task clock, model time, browser time, provider charges, caller-model usage when present, failed attempts and cleanup. Keep native engine advantages visible rather than forcing every project through agent-browser. Repeat several task types, including absent targets, similar autocomplete options, delayed content and longer multi-screen work. The current runner establishes one controlled same-stack comparison. Broader claims require native adapters, credentials and repeated longer tasks for the other projects.
