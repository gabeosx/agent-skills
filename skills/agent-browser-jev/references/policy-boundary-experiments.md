# Picker authority and ranked eligibility experiments

September 30, 2026, pending Agent Browser Jev **1.3.0**. This follows the [implementation comparison](implementation-approaches.md). The retained change is narrow: establish individual eligibility before ranking, separately assess base collection identity, then preserve the original target set through effects. The attempted action-local picker rewrite is rejected.

## What was compared

All arms used Jev 1.13, SDK 1.3.2 and the original caller goal. No caller supplied a browser plan, resolved a target or intervened. Runtime sources, fixtures, cohorts, limits and promotion criteria were frozen before scoring. Local trials assigned fresh server state before arm navigation and checked server events separately from completion claims. No-model controls reached the intended records through rendered controls and checked wrong effects. Qualification corrections and failed controls remain recorded.

These are self-authored fixtures and practiced public MiniWoB families. New labels, layouts or seeds do not make them unseen families or an independent holdout. Original public WebArena mutation cases had exhausted their allowed attempts and were not rerun. This campaign adds **no WebArena score**. Existing verified backend restoration remains harness evidence, not task success.

## Action-local picker authority did not transfer

A rollback comparator retained current mechanical observation fixes but used the earlier pre-picker decision policy. B was the retained readonly-display build. C limited picker assessment to a proposed option, completion or dependent operation, allowing unrelated preparation to proceed.

| Authored cohort | Earlier policy A | Current B | Action-local C |
| --- | ---: | ---: | ---: |
| Development, correct goal and complete report | 4/4 | 3/4 | 4/4 |
| Reserved instances, correct goal and complete report | 4/4 | 3/4 | 4/4 |
| Separate absent-target negatives | 2/2 | 2/2 | 2/2 |
| Total Jev calls, including negatives | 101 | 116 | 127 |

B violated requested field/selection ordering on both order-sensitive instances and reported completion. C repaired those authored workflows but required more calls. A also completed them; this is evidence against indiscriminate authority layering, not a universal rollback victory.

Public reward comparisons rejected C and two justified repairs:

| Practiced MiniWoB sample | Comparator full rewards | Local-picker full rewards |
| --- | ---: | ---: |
| Six families, seed 10417: A versus C | 5/6 | 4/6 |
| Six families, seed 10419: B versus C2 | 4/6 | 3/6 |
| Three picker/date families, seed 10423: B versus C3 | 2/3 | 0/3 |

A separate B arm at 10417 reached 5/6. It solved flight booking and missed date selection, while A did the reverse; no general winner follows. C2 removed a circular requirement that an option already be selected before selecting it. C3 added an assessment of whether an operation consumes picker values, including Search classified as navigation. Neither established public benefit. The final autocomplete trial exhausted decisions after typing a query; final flight booking searched without committing airports.

Reward, scope and reporting differ. At 10419 B reached the flight goal and returned control; that is rewarded work with incomplete reporting. Both arms reported the unsuccessful date task complete. Additional public action scope is not globally verified. All public failures and source hashes are retained, including the three rejected picker variants. **No picker rewrite was promoted.**

## Eligibility must precede ranking

The existing ranked contract bound metrics and sorted all objects; it did not separately establish each object's eligibility before applying the count. The first candidate added independent item eligibility questions alongside metric binding. Code filtered eligible objects, checked count and rank-boundary ties, and preserved fixed identities even when effects changed scores.

On four mixed-owner/topic authored positives, correct scoped completion rose **1/4 → 4/4**. Both versions nevertheless acted on a differently named collection and reported completion. The candidate's other insufficient-members negative passed. The promotion gate therefore failed.

A second candidate included collection labels and a batched collection-identity Choice. It again completed 4/4 positives but still accepted the wrong named collection. Its actual answer said the collections matched despite having the conflicting root label. This was a semantic failure, not merely missing evidence.

The final candidate separated base collection identity into a focused Noul request containing only the original goal and observed collection labels. Item eligibility and metric selection receive the goal, collection labels and item evidence; they receive no earlier ranking answers. The ordinary 0.5 decision boundary is **not a calibrated safety probability**. Code rejects malformed answers, uncertainty, insufficient eligible objects and unresolved ties; it cannot certify the semantic answers.

The original six cases had reached their attempt ceiling. Six fresh authored instances were predeclared with changed collection, author and topic names. These remain the same practiced family.

| Final paired sample | Retained B | Focused identity plus eligibility D3 |
| --- | ---: | ---: |
| Positive goals reached with correct action scope | 1/4 | 4/4 |
| Those goals also reported complete | 1/4 | 4/4 |
| Separate negative cases passed | 0/2 | 2/2 |
| Trials with wrong effects, including negatives | 4/6 | 0/6 |
| Jev calls, including negatives | 33 | 47 |
| Model cost, including negatives | $0.001905 | $0.002938 |

Both candidate negatives returned unfinished control. They do not count as positive completions. One allows an authorized partial effect but forbids substituting another owner; the other requests an unavailable named collection. The first two scope variants and every wrong effect remain visible rather than being pooled away by the final successful sample.

## Retained change and its limits

Only the ranked-contract change was retained. It establishes base identity, filters eligibility before numeric or displayed-order ranking, checks the requested count and preserves original identities through later score changes. General action selection, picker policy, caller assistance and automatic traversal defaults remain as previously retained.

The full offline suite passed **418 tests**. Real-browser regression reached **3/3** previously passing batch goals with correct scope and complete reports: a prefixed collection name with displayed ranking, grouped numeric metrics, and a 110-record author collection. The existing component matrix passed **27 positive goals and complete reports plus one separate absent-target handoff**. These checks do not prove unfamiliar workflows or public WebArena improvement. Independent caller effort was not exercised; caller interventions were zero in this campaign.

Private evidence lives in `.runs/policy-boundaries-20260930/`: plans, authorization, frozen sources, no-model qualification, raw reports, rejected repairs, retained runtime diff, source audit, metering and cleanup. The [capability status](capability-status.md) and [persistent dashboard](http://127.0.0.1:8765/) distinguish this local ranking gain from public picker regressions and prior real-caller scores.

The engineering lesson is supported narrowly: separate eligibility from arithmetic, and give a collection identity question only the evidence needed for that relation. Adding a semantic check to a larger batch did not solve the wrong-collection failure. Limiting specialist authority sounded plausible but failed public transfer; it needs a different diagnosis before another implementation attempt.

Additional measured model spend was **$0.184024**, matching provider usage exactly. Conservative cumulative accounting is **$31.115031 / $40**, with **$8.884969** remaining and prior reserves intact. Paid work stopped at 15:37 UTC, before the 15:42 UTC deadline. Both skill structures, 126 local links, release contract and whitespace checks passed. Scoped browsers, servers, public containers and component temporary files were removed; the dashboard and evidence were preserved. No commit, publication or global installation occurred.
