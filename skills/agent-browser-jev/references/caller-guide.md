# Caller guide for specific controls and recovery

Use the relevant section when preparing calculations, diagnosing a handoff, or accepting a complex multi-object outcome. Ordinary delegation and continuation commands are in [the skill entrypoint](../SKILL.archived.md).

## Delegation boundaries

Delegate coherent work on observed accessible controls. For the boundaries below, handle the specific blocked step and let Jev continue supported work. The caller does not need to supply an end-to-end plan or read experiment reports to use these instructions.

| Limitation | Best caller response |
| --- | --- |
| Authentication, downloads, tab management, keyboard-only pickers, or visual/drag-only interaction | Use caller browser tools for that step. Verify its result, then resume from the current page with the intervention in `--context`. Do not ask Jev to perform the same unsupported gesture again. |
| Missing final prose, personal facts, or arithmetic beyond the supported numeric binding | Compose authorized content or compute the exact field value and pass it with `--value`. Ask the user only for genuinely missing facts or choices. Jev can compute amount/percentage edits for separately identified records and fields, retaining each original value to prevent reapplication. Repeated work requires stable observed identity; fractions, formulas, cross-field calculations and required rounding need caller derivation. For dates, Jev can select a bounded civil-calendar calculation from an explicit ISO or English date in the goal; an absent anchor, ambiguous week boundary, business-day calendar or timestamp/timezone conversion needs caller derivation. |
| Readonly displays, autocomplete queries, or rejected/transformed input | Let Jev inspect and click accessible options; never fill a readonly display or accept a typed prefix as a committed choice. After `input_not_accepted`, inspect the current value and compatible control before continuing. Do not silently truncate, normalize or retry an unrepresentable value. |
| Semantic discovery, cross-page relationships, or ranked collection coverage remains unresolved | Start with the original goal, including ambiguity the site can resolve. If Jev stalls, inspect the missing relationship or collection coverage with caller tools, establish the specific fact or perform that step, then resume. An empty search or satisfied per-target ledger does not prove that all matching objects were found. |
| Incomplete, changing or very large page capture | Re-observe with caller browser tools and inspect the controls needed for the remaining step. Allow rendering to settle when the page is still changing; an empty body or truncated view does not establish absence. Resume the original goal with any established context, and count caller work that resolves the return as assistance. |
| A workflow has demonstrated wrong field binding or premature saving | Delegate bounded preparation, inspect the requested fields, and have the caller perform the commit when needed. Check the saved state and unintended changes. For other workflows, delegate the full authorized goal and assess the returned evidence; a failed control or application error does not make its entire family unsupported. |

Caller composition, derivation, discovery and direct gestures that advance unfinished work must remain visible as assistance; acceptance of an already-reached goal is distinct. Describe what Jev achieved before takeover and what the caller supplied. Use the [capability scorecard](capability-status.md) for the evidence behind these limits, rather than treating every weak area as unavailable. Uploads require a user-requested exact absolute path supplied as a value; never invent a path or pass secrets as task values.

When a requested field or option is missing, establish whether adding it affects only the current record or a shared schema, template, or attribute set. A control inside a record editor can immediately change shared configuration without saving that record. A request to create or edit one record does not by itself authorize that broader change. Preserve the unresolved requirement when the available options cannot express it; do not silently substitute an option or claim completion.

## Exact values and field binding

Supply known exact text up front. Repeat `--value name=text` for non-secret titles, field values or authorized content. Jev can copy observed text, extract exact goal spans and bind a supported relative numeric change; code performs the exact arithmetic. It can also select code-computed calendar dates from an explicit date in the goal: day/week/month/year offsets or calendar-period boundaries. Code never supplies an ambient today date; verify the anchor, relation and accepted field format. It does not compose missing prose or invent personal facts. The calling agent can compose content within the user's request and supply it; ask the user only for facts or choices that actually need them.

When a later field needs a value already present in the goal, Jev can resolve that field from a fresh observation even after earlier speculative field checks. This uses the existing decision budget; it does not reuse a stale field binding or guarantee that the assignment is correct.

For supported relative arithmetic on a populated field, Jev can attempt a bounded source binding before choosing its next gesture. It establishes the record before comparing that record's prior field edits; an unresolved speculative check returns to ordinary action selection. A computed proposal does not perform or reserve an edit, and a prepared value does not prove saving. Check the requested record, original source and saved result rather than inferring completion from a successful calculation.

Describe what each value is for. Use keys such as `title`, `message` or `contact_prefix`, and keep the assignment in the goal. Use an observed field label when already known; no preliminary inspection or full plan is required just to name a value. Keys are semantic hints, not selector bindings: code does not restrict a value to a field with a matching name. For a numeric amount input with a separately displayed unit, Jev may select the exact numeric substring from the supplied goal; verify that it matches the input format. This does not permit currency conversion, rounding or removal of symbols from literal prose or identifiers. A search prefix can prepare discovery before the full item is visible; selecting and committing the item still requires all requested predicates. Observed text fields retain bounded descriptive class and ARIA hints when available; these help Jev interpret a control but do not prove that an item has been selected. Review guards distinguish the query field from the eventual target. Their judgments can still conflict or reject a valid action, so inspect a returned handoff instead of treating it as proof that the task is impossible.

## Large or incomplete observations

Large observations preserve form fields and selected values together when a closed native dropdown has a long option inventory; inspect the accompanying option windows to choose another value. Exact duplicate native options retain their select owner instead of becoming detached click targets. Captured windows are parts of one observation, not additional website pages. Compact table cell labels and large table/form windows retain observed control ownership and containing-record text from that same capture; this helps distinguish unnamed controls, but does not prove that a record satisfies the goal or that all matching records have been found. For unnamed or icon-only text fields, observed placeholder and tooltip hints help identify the field; they remain page evidence, not authorization. When repeated Edit controls refer to different records or address types, use their visible headings to establish the target; ask the caller to resolve a material ambiguity instead of assuming that either record is interchangeable.

## Completion assessment

Every completion proposal and unresolved input request receives a budgeted Jev review of the original goal and observed outcome. An unrelated empty field need not require caller input after the goal is established; otherwise the original missing-input request remains. This is a second assessment by the same model, not independent verification. Match the requested object identity before accepting its status. In an existing object’s edit form, attributes identifying the requested object are constraints for finding it; changing those attributes does not select a different object. A record’s detail heading and identity fields can establish the current target; checking one eligible member does not establish that an entire requested set is finished. Supplying an entity’s exact name or code to an autocomplete still requires verifying the selected entity.

A populated text field can still contain the old value when Jev reports completion. For an exact-text assignment, compare the requested text with the native field value and the saved readback. Preserve whitespace and omitted-value uncertainty; matching displayed text alone does not establish exact bytes or a committed outcome.

For a request to open an item's details or settings, confirm that item's own view or requested dialog is open. A matching row or link in a collection establishes discovery only. The completion review separately classifies the requested destination and the current kind of view; conflicting classifications keep the goal unfinished. These classifications are model assessments and still require caller verification. A collection is the correct destination when the caller requested the collection itself.

Historical action readbacks can support acceptance of work already performed. Assess them together with the original goal, current observation and later actions: check target identity, requested scope, collection coverage, omissions and any evidence that earlier state was superseded. A tool-success label or number of actions alone does not establish the outcome. Revisit a page when needed to resolve missing or conflicting evidence, rather than automatically repeating every earlier readback. Historical references still must not be replayed for actions.

For relative edits, use the compact historical field evidence to establish the original value, then check the current saved value against the requested change. Do not repeat an increment to verify it. Before rewriting an existing value to preserve it, read its exact native value; accessibility display text can collapse whitespace. Do not normalize unrelated fields while completing the requested edit. If the accessibility capture omits visual state, inspect a browser screenshot or the rendered control with caller tools; absence from the text capture is not evidence that a rating, selection or control is absent. When a search returns nothing, a shorter exact fragment from the caller's target can help discovery, but verify the identity and complete requested set before changing anything.

The optional `executionContract` records bound targets and per-target progress for repeated effects. For ranked subsets, Jev assesses collection identity and each object’s eligibility before code applies ranking and count; bound identities persist through effects that change scores. Identity, eligibility and satisfaction remain model assessments. Capture windows cover one accessibility capture, not necessarily every website page; a satisfied ledger alone cannot prove whole-site coverage or correct author matching.

An incomplete return can follow a successfully reached goal. If the evidence establishes every requested outcome, finish without another gesture and retain Jev's original return reason. Report caller-verified completion and any caller assistance accurately. A handoff alone does not prove completion. Independently verified goals reached before return can count as autonomous outcomes when no caller work advanced them; retain the non-complete return separately.

## Narrow recovery

Resolve the specific boundary, then resume remaining routine work. For a derived value, inspect the observed source and requested relationship, compute the authorized exact value, and supply that field value; this does not require an end-to-end browser plan. Count caller reasoning and supplied derivations as assistance even when Jev performs every browser gesture. After a caller action, explain it with `--context "Dismissed the account notice; continue from the current page"`. A changed context or unmappable target can stop a saved execution contract for review; do not omit a real intervention to evade that check. If the same boundary recurs without useful new evidence or state, take over instead of repeatedly resuming unchanged. Preserve completed work when deciding how to continue.

If a picker prefix went into a general search field and Jev then requests the full value, repeating or renaming the prefix is not a reliable recovery. Inspect the actual selection control, enter the supplied prefix there when supported, choose a goal-consistent observed option, verify the committed selection, and resume the remaining work. This is caller assistance; a lookup alone neither commits the selection nor establishes that the requested option is absent.
