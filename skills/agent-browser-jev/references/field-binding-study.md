# Field binding and release candidate review

Reviewed 2026-09-30 for pending **Agent Browser Jev 1.3.0**. The retained runtime remains the grounded flat controller, with focused semantic bindings and code-owned exact values, arithmetic, browser mechanics and continuation state. This study rejects an additional destination classifier and checks practical caller recovery. It introduces no public-benchmark performance claim.

## Experiment and qualification

The hypothesis was that a focused Jev Choice among complete value/destination actions would improve binding when the same exact supplied text was available for multiple fields. The private candidate offered observed destinations, exact replacement or supported append actions, and a none choice. Search preparation remained available, and accepted bindings still passed through the existing action review. Neither actor received fixture answers, task identifiers or evaluator state.

Six authored positive development cases cover a search decoy, parent versus child notes, preserving an addition, assigning two values, a prefix picker and preparation without saving. Two separate negative boundaries cover a missing requested person and missing derived data. Four reserved authored positives change labels, numeric-looking prose, duplicate value aliases and picker terminology; a fifth reserved case lacks a personal value. These are new authored variants in practiced families, not independent public tasks or unseen-family coverage.

Rendered fills, option clicks and saves proved positive reachability before scoring. Independent readbacks and fresh page loads proved restoration between arms. Early failed qualification records remain preserved: a native clear event preceding an exact fill needed a narrow verifier correction. An empty event is accepted only immediately before the exact requested refill of the same field. Transient wrong field edits still fail, even if later corrected.

Global search is outside the record form. An uncommitted lookup using a fixture-declared goal-related term is preparation; it cannot satisfy a picker, reply or saved goal. The original strict audit counted such lookups as wrong record edits and, in the caller case, required the search box to remain empty for a saved record to pass. Raw reports remain unchanged. Supplemental reviews are bound to the exact report hash, case and arm; they assess actual record fields and separately retain query counts. Arbitrary prose in search, wrong record edits and premature saves remain failures.

The final automated review initially omitted the observed query `Tomas’s review`, despite allowing `Tomas`. That exact goal span is legitimate lookup preparation. Its failed dashboard check and review are preserved; a verifier-only correction and regression align the final automated review with the earlier independent assessment. No model retry or runtime change was needed.

The prefix picker remained unfinished in both arms: Jev entered the supplied prefix in Global search and requested a full value without selecting or saving. The other five positive workflows completed. The additional classifier added six requests and $0.000628362 without a scoped completion gain, so it was not promoted.

A third and final invocation on that picker renamed the value key from `prefix` to `contact_prefix`, preserving the goal and exact value. It again returned `input_required`, with six requests and no saved goal. Value names are useful semantic hints, but this diagnostic establishes no recovery benefit from naming alone. That case has reached its three-invocation allowance across all arms.

## Retained controller and independent caller

Three other reserved positives all reached correctly scoped goals and reported complete; the missing-personal-value negative returned `input_required` without an effect. Those four single-arm trials used 32 Jev requests and $0.003711288. They are regression checks without a matched improvement claim.

The reserved picker also received a separately qualified three-arm comparison. An independent GPT-5.4 caller had only observed browser controls, the original goal, exact supplied values and installed skill guidance. It had no access to fixture source, expected state or evaluator results.

Jev alone selected Harbor Annex and saved while preserving Memo. In the assisted arm, the caller supplied redundant context and chose a ten-action helper budget. Jev searched globally and handed back. The caller inspected Destination, entered the already-supplied prefix there, clicked the observed Harbor Annex option and saved. This is natural independent caller recovery, not a scripted intervention or a forced interruption. Its reasoning and three gestures remain assistance. No helper resume was needed.

All final record goals pass the supplemental review. The assisted raw strict flags remain failed because Global search still contained `Har`; that query was not a record mutation. The reviewed result does not establish that delegation is cheaper, more reliable or preferable: it cost more than direct execution, and the initial Jev result varied despite the same retained runtime. Only one picker instance was compared. The delegated caller was required to start with Jev, so this measures recovery rather than its independent choice of whether to delegate.

The caller tool description used the ambiguous shorthand `get text/value REF`, causing two rejected read commands in the direct arm. The maintained harness now spells out `get text REF` and `get value REF` as separate argument arrays. The measured trial used the original description; no improved caller score is claimed for this clarification.

## Operating guidance and disposition

The [skill entrypoint](../SKILL.archived.md) now explains that value keys describe roles rather than enforce selectors. If a supplied prefix went into general search, callers should inspect the actual selection control, choose a goal-consistent observed option and verify the committed record, rather than repeat the same value. A failed picker does not make all accessible pickers unsupported. Known wrong-binding or premature-save workflows warrant bounded preparation and a caller commit; other goals can still be delegated whole.

The runtime candidate was rejected. The useful retained changes are operating guidance, a maintained independent field-binding harness and verifier regressions, an independently observed recovery example, and dashboard corrections that expose both reviewed and raw negative flags. Earlier relative numeric, picker, collection and public-task evidence retains its original source attribution. No additional WebArena run was made in this campaign.

The retained release candidate passes **432 offline tests**, both affected skill structure checks, **139 local documentation links**, and the release contract against `HEAD`. The persistent localhost dashboard and preexisting shared benchmark image remain available. Nothing was committed, published or installed globally.
