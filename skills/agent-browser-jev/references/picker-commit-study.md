# Picker selection and completion evidence

The pending 1.3.0 helper now handles observed custom comboboxes through field-specific Jev bindings. Matching query text is separated from evidence that a record was selected. Jev identifies the required field, chooses a supporting readback or an observed option, and decides whether an empty picker needs an authorized query fill or opening. Every proposed gesture still passes ordinary action review and permissions. The caller supplies the goal and known values, not a browser plan.

The first frozen transfer comparison completed **4/4 authored positive goals with correct scope and complete reports**, versus **3/4** for the baseline. Both passed one separate missing-target negative. Calls increased **30 → 38** and cost **$0.002955 → $0.003461**, about 17%. No caller intervened; actual caller recovery effort was not measured. These are fresh authored instances of practiced controls, not unseen-family coverage.

## What changed the outcome

Adding picker structure to the existing questions alone did not help. A pending-selection veto improved one development task but also withheld a legitimate option click. Completion-only review replaced a false completion with a handoff and initially regressed an already-selected case. More explicit inspection descriptions and detailed feedback still failed to produce the missing work.

The useful change was to bind decisions to concrete evidence and controls: which field requires a record, which current or executed readback supports its selection, and which observed option belongs to that requirement. Sharing that binding with action review prevented the review from independently mistaking query equality for an already-completed selection. These remain fallible model judgments; code does not prove the selected record's meaning.

A first version regressed a search-driven contact picker. Its preparation question repeatedly chose opening and lacked execution history. The retained version supplies readbacks and offers remaining permitted preparation gestures for the same field value, followed by normal review. A changed value permits fresh inspection. All failed variants and the query-picker regression remain in the private evidence.

## Detached suggestions and missing targets

The eight-family public comparison did not activate the custom-combobox route. Flight inputs expose ordinary textboxes and detached suggestion lists. The next candidate uses the actual successful fill and its current readback to propose a possible field/list relationship. Jev must establish that relationship. Search results, unrelated lists, optional suggestions and explicit literal-text goals retain their different meanings.

That extension achieved the previously missed booking at seed 8812, then reached **3/3 official goals versus 2/3** in a paired three-family sample at seed 8927. Both arms reported **2/3 complete** and handed back the flight; the candidate had booked it. Calls rose **40 → 59** and cost **$0.006953 → $0.011838**. Action/readback review confirmed the correct airports, date and cheapest of the three offered flights. These are practiced families and development-informed fresh instances.

An authored absent-target case exposed two separate semantic failures. Joint goal/state classification treated an unavailable office as literal query text, then saved an empty selection. Separating the caller requirement from available options corrected that interpretation but selected a different facility and falsely reported completion. Both variants are preserved and rejected as final behavior.

The retained route asks focused Noul judgments about each offered item's full requested identity in the same request as target selection. It consumes only the proposed target's judgment and retains ordinary action review. Its `> 0.5` rule is the binary decision boundary, **not a calibrated probability of safe action**. A proposed 0.8 cutoff was rejected in a captured probe because it would also withhold a valid autocomplete item. See the [official primitive definitions](https://docs.typesafe.ai/primitives); no independent correctness guarantee follows from the typed answer.

The final authored retry retained **5/5 positive goals, correct scope and complete reports**, and returned the missing-target case without selecting or saving a substitute. Literal queries, optional suggestions, article results and unrelated bookmarks remained correct. This set is exhausted development data, not a holdout.

The retained build then passed **27/27 component positives and one separate negative** at seed 9140, plus **4/4 earlier custom-picker transfer positives and one negative**. It preserved the seed 8927 public results on a candidate-only regression: **3/3 goals, 2/3 complete reports, one achieved-goal handoff**.

At fresh seed 9031 the paired public result was **2/3 versus 1/3 official goals and complete reports**. Calls rose **35 → 55** and cost **$0.007097 → $0.009407**. Both arms failed the shortest-flight task. The candidate selected both full airport names but a subsequent condition review incorrectly blocked Search while waiting for the shortest-flight evidence that Search would reveal. The autocomplete difference began before the new picker route, so that win alone is not causal evidence for the route. Scope review covers all six executions. There was no caller intervention or measurement of real caller recovery effort.

The public working checkpoint passed **408 offline tests**, including tests that goal interpretation excludes current options, malformed Noul responses cannot authorize a selection, and the independent verifier retains wrong effects. The caller-context/scope cache invalidation correction was checked offline after the frozen live snapshot; it changes no semantic question.

## Discovery-condition experiment held back

The shortest-flight failure motivated one further experiment: a focused Noul question about whether the immediate action only discovers information, alongside the existing condition review. It could release an already-approved action only when that later condition review had classified it as unresolved. It could not reopen a primary action rejection or an opaque control.

A captured failing Search and twelve authored counterexamples were classified as intended. Five rendered positive workflows and two negatives tied the retained build, but did not activate the new question. A targeted retry booked the shortest flight and earned full reward while handing back; however, the old condition question also changed to a permitting answer. The new override was not used.

The fresh six-family plan at seed 9347 was interrupted by a provider HTTP520 on the candidate flight, before any browser action. The measured baseline booking and failed candidate are preserved as an incomplete pair. The five unstarted pairs subsequently completed **5/5 goals and complete reports in each arm**. After metering recovery, a separately labeled candidate-only flight retry reached full reward and reported completion, while the original measured baseline had achieved the goal and handed back. Its old condition answer also permitted the action without the new override. Action scope was independently reviewed for these runs.

This experiment is **not retained in the default helper**: it has no demonstrated live benefit attributable to the new decision. Its diagnostic recovery is not substituted for first-attempt results, and its new question is not credited for a gain when the existing question already allowed the action. Two provider failures across this campaign retain **$0.02** additional reserve in total, even though aggregate provider usage matched known charges at reconciliation.

## Limits and evidence

The specialized route requires complete, bounded observed evidence. A recently filled ordinary textbox can now enter a provisional route when a current list of choices is visible. Jev first distinguishes field suggestions from search results or unrelated content; code does not invent an ARIA relationship. It uses at most eight distinct observation assessments and twelve proposed picker actions per step, within the caller's smaller overall budgets. Unknown relations, absent observed options, withheld actions or exhausted bounds can still return control. Keyboard-only and visual-only widgets remain outside its contract.

Private plans, frozen sources, raw failures, no-model rendered controls, independent event verifiers, classifier probes, source hashes and per-pair public reports are retained in `.runs/picker-commit-20260929/`. The public [capability summary](capability-status.md) keeps these narrow results separate from earlier MiniWoB and WebArena evidence.

Campaign measured spend is **$0.252435**, exactly matching the provider usage increase; **$0.02** additional reserve remains for two failed requests. With all earlier reserves preserved, conservative cumulative accounting is **$28.625818 / $40**, with **$11.370489** remaining under the current authorization. Both skill structures, release contract and local links pass. WebArena restoration and official evaluator controls were requalified on the current harness without paid scoring, and campaign-owned resources were removed. Pending versions remain Agent Browser Jev **1.3.0** and Benchmark Improvement Loop **1.1.0**; nothing was committed, published or installed globally.
